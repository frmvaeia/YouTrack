# YouTrack

Клиент: `scripts/yt.py` (только stdlib Python 3). Путь ниже — относительно этого файла:

```bash
YT=".claude/skills/youtrack/scripts/yt.py"
python3 $YT me                       # проверить доступ
python3 $YT issue ABC-123            # карточка: поля, описание, связи, комментарии, вложения
python3 $YT links ABC-123            # связанные задачи по типам связей
python3 $YT history ABC-123          # изменения полей (таймлайн статусов)
python3 $YT search "project: ABC #Unresolved" --top 50
python3 $YT analyze ABC-123 --depth 1   # аналитика по задаче и связанным
python3 $YT context ABC-123 --depth 1   # все тексты графа + строки, похожие на требования
python3 $YT comment ABC-123 --file checklist.md   # ЗАПИСЬ — только с согласия пользователя
```

`--json` перед командой (`python3 $YT --json issue ABC-123`) даёт сырой JSON.

## Настройка

- `YOUTRACK_URL` — адрес инстанса. Берётся из переменной окружения, `~/.config/youtrack/env` или `config.env` рядом с этим файлом (там уже `https://youtrack.wildberries.ru`).
- Токен (`perm:...`):
  - **облачная сессия** — network secret окружения для хоста YouTrack; прокси сам добавляет заголовок `Authorization`, переменная `YOUTRACK_TOKEN` не нужна;
  - **локально** — `YOUTRACK_TOKEN` в окружении или в `~/.config/youtrack/env`.

Токен никогда не коммить в репозиторий и не выводи в ответах. Если `me` отвечает `401` или `cannot reach` — скажи пользователю добавить network secret (или токен локально), не проси вставлять токен в чат.

## Сценарии

### 1. Аналитика по таске

1. `analyze ID --depth 1` (для эпиков и цепочек зависимостей — `--depth 2`; глубже — только по просьбе, запросов становится много).
2. При необходимости дочитай отдельные задачи через `issue` и `history`.
3. Ответ — коротким отчётом:
   - **Статус и возраст**: состояние, исполнитель, сколько дней открыта, время в каждом статусе, сколько раз переоткрывали.
   - **Связанные задачи**: таблица, прогресс (решено N из M), открытые блокеры/зависимости.
   - **Трудозатраты**: spent time по задаче и всему графу, по людям (если в проекте включён time tracking).
   - **Риски**: открытые зависимости, долгие простои в статусе, переоткрытия, задачи без исполнителя, противоречия между описаниями задач.
   - Чем завершить: 2–3 конкретных вывода или следующих шага.
   Цифры бери только из вывода скрипта, ничего не додумывай.

### 2. Сбор информации из связанных задач

`context ID --depth N` выводит описание и комментарии каждой задачи графа и сам граф связей. Учитывай направление связи: `depends on`, `is required for`, `parent for`/`subtask of`, `duplicates`, `relates to`. Подзадачи и зависимости — источник требований; `relates to` — только контекст.

### 3. Чеклист по требованиям

1. `context ID --depth 1` (подзадачи и зависимости включаются автоматически).
2. Раздел «Requirement-like lines» — лишь подсказка (маркеры списков, AC, Given/When/Then, «должен/необходимо/нужно/must/should»). Читай тексты целиком: требования бывают в обычных фразах и в комментариях (уточнения в комментариях важнее исходного описания, если они позже).
3. Оформи чеклист в Markdown:

```markdown
## Чеклист требований: ABC-123 — <summary>

### Функциональные
- [ ] <атомарное проверяемое требование> — источник: ABC-123 (описание)
- [ ] ... — источник: ABC-130 (комментарий Ивана, 2026-10-01)

### Нефункциональные / ограничения
- [ ] ...

### Зависимости
- [ ] ABC-125 «Backend API» решена (сейчас: In Progress)

### Открытые вопросы
- <противоречие или неясность, которую нужно уточнить у автора>
```

Правила: одно требование — один пункт, формулировка проверяемая; у каждого пункта источник (ID + описание/комментарий); дубли из разных задач сливай; противоречия не решай сам — выноси в «Открытые вопросы»; уже выполненное (задача решена, чекбокс `[x]`) отмечай `[x]`.

4. Покажи чеклист пользователю. Публиковать в YouTrack (`comment ID --file ...`) — только если пользователь явно попросил.

## Ошибки

- `HTTP 401` — токен неверен или отозван; `403` — нет прав на проект; `404` — неверный ID или `YOUTRACK_URL` (проверь суффикс `/youtrack`).
- `cannot reach` — неверный URL или хост не разрешён сетевой политикой окружения.
- Поля статуса/исполнителя ищутся по именам `State/Status/Состояние/Статус`, `Assignee/Исполнитель`, `Type/Тип`, `Priority/Приоритет`. Если в проекте поля называются иначе — смотри `--json issue` и бери значения оттуда.
